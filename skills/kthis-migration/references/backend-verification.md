# 后端验证与落库核对（无测试框架）

> 前提：新侧**没有可用的测试框架**（各 `AppTest` 都是 `assertTrue(true)` 桩）。后端验证 = **编译/启动 + 接口自测 + 落库核对 + 与遗留行为比对**。结论只写「做了哪些检查、结果如何」，**不要声称「测试通过」**。

## 1. 编译与启动

```sh
./startup.sh dev                                                      # 编译 + 启动（最快）
mvn -pl webhis-<mod>-server-impl -am install -Dmaven.test.skip=true   # 只校验单模块
```

- 其余入口（`build` / `start` / `debug` / `stop`）、单模块构建细节与环境要求（JDK 8、`settings.xml`、端口 9800/Swagger 可单独试接口）见 [backend-porting.md](backend-porting.md) §13。

## 2. 接口自测（逐个端点）

| # | 检查 | 通过标准 |
| --- | --- | --- |
| E1 | 正常路径 | 最小必填 + 完整字段各跑一次，返回结构与值正确 |
| E2 | 响应形态 | 确认是裸 VO/List 还是包装（仓库两种风格并存），不按惯例假设 |
| E3 | 入参校验 | 缺必填、类型错、超长、非法枚举 → 报错信息明确（不是 500 堆栈） |
| E4 | 业务校验 | 唯一键重复、外键不存在、状态不允许 → 抛 `BizException` 且 `errorCode`/提示语与设计文档一致 |
| E5 | 分页 | 首页/末页/越界页/pageSize 边界；`total` 正确；排序稳定 |
| E6 | 鉴权 | 带 token 正常；无 token → `AUTH_EXPIRED`；应免登录的接口确实免登录 |
| E7 | 幂等/重复提交 | 同一请求重复提交不产生脏数据（或被业务拒绝） |

> 提示语要回 **设计文档「数据流程与接口」册的「服务端异常 → 前端提示」** 对照，两边不一致时以源码为准并回改文档。

## 3. 落库核对（Oracle 只读查询）

每个写操作都要回查数据库，不能只看接口返回：

| # | 检查 | 通过标准 |
| --- | --- | --- |
| D1 | 添加 | 记录存在；`created_by` / `created_date_time` 被框架自动填（不是 null、不是调用方乱填） |
| D2 | 修改 | `last_updated_by` / `last_updated_date_time` 变化；**未涉及的字段没有被覆盖**（`setModified` 语义） |
| D3 | 删除/停用 | `defunct_ind` = `'Y'`，记录仍在；默认查询过滤 `'N'`，列表里消失 |
| D4 | 多院区 | `entity_mstr_id` 写入正确；跨院区数据不串 |
| D5 | 编码类字段 | 按编码生成规则生成（前缀/流水/补零），与设计文档一致 |
| D6 | 一对多 | 主从表行数、外键、顺序字段（`seq`/`sort_no`）正确，删除时从表一并处理 |
| D7 | 事务回滚 | 故意让第 N 步失败，确认前面写入**全部回滚**，不留半截数据 |
| D8 | 审计/并发 | 并发改同一条记录时 `last_updated_*` 与版本/时间戳表现符合预期 |

## 4. 与遗留行为比对（前端 / 后端通用）

1. 同一场景在**遗留系统**跑一遍，记录：字段值、默认值、计算规则、提示语、落库结果。
2. 新侧跑同一场景，逐项对齐。
3. 出现差异时判定性质：**有意的等价替换**（技术栈/控件差异）还是**实现错误**（必须修）。判定不了就问用户，不要默默放过。

## 5. 回归

- 重跑本模块前序已完成的接口（按 `_进度台账.md` / 设计文档的阶段清单）。
- 改动落在公共 `-server` / `-common-*` 模块时，重跑**所有受影响的域**的关键接口。
