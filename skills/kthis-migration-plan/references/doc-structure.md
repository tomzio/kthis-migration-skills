# 目录结构与文档约定

> 本文件定义迁移文档的**形态**（放哪、叫什么、怎么编号、怎么互相引用）——都是**通用规则**，与具体模块无关。
> 迁移文档根目录默认 `docs/migration/`（脚本 `--root` / `--docs-dir` 可覆盖）。

## 1. 位置

```text
<迁移文档根目录>/
├── README.md                 # 全局索引
├── 00-前端布局规范.md          # 跨模块布局基准（只一份，可选）
├── images/                   # 全模块共享截图目录
└── <NN>-<模块名>/             # 每个功能模块一个目录
```

- `<NN>` 两位序号（`01`、`02`…），与迁移清单 / 既有文档保持一致；`00` 保留给跨模块通用册。
- `<模块名>` 用中文功能名，不用代码代号。
- 截图建议放迁移文档根目录下的共享 `images/`（用**文件名前缀**区分模块）；大模块也可在本模块目录内自建 `images/`。两种都被 `audit-docs.sh` 识别。

## 2. 册（volume）划分原则（最重要）

1. **按界面 / 功能聚合**，不按代码分层。
2. **弹窗的每个页签单独一册**（避免第一版巨型文档）。
3. **弹窗外壳单独一册**（只写外壳，页签正文各归各册）。
4. **共用内容单独一册**：被多个界面共用的页签、共享分区 → 复用矩阵册；**只维护一处**。
5. 收尾固定三册：**数据流程与接口**、**迁移实施计划**、**共享分区与复用矩阵**（顺序可微调但要连续）。
6. 编号**从 00 连续**，不跳号；`00` 必为「总览与通用约定」。

**每册内部统一顺序**（界面类分册）：

```text
（适用条件/参数，可选）→ 功能布局（含线框与布局要点）→ 控件顺序 → UI 交互 → 关联事件 → 实现要点 → 关联文档
```

- 「适用条件（参数）」只在受系统参数 / 权限控制时出现。
- 「功能布局」节末尾含**线框与布局要点**（本界面 ASCII 线框 + 布局要点）；末节「实现要点」只列本册特有实现做法。
- 通用骨架 / 栅格 / 实现做法引用跨模块的 `00-前端布局规范.md`（骨架与栅格见 §3，通用实现清单见 §3.5）。

**册序通用形态**（把 `<...>` 换成实际内容，可按需增删页签/弹窗）：

```text
00 总览与通用约定
01 主页面
02 <弹窗甲>编辑弹窗外壳
03..k <弹窗甲>各页签（每页签一册）
     <弹窗乙>编辑弹窗外壳
     <弹窗乙>各页签
     <独立弹窗>
     辅助弹窗与码表
     数据流程与接口
     迁移实施计划
     共享分区与复用矩阵
```

## 3. 文件与命名

| 项 | 规则 |
| --- | --- |
| 册文件 | `<NN>-<册名>.md`，册名用中文界面名 |
| 册名后缀 | `主页面` / `…编辑弹窗外壳` / `…页签` / `…弹窗` |
| 台账 | `_进度台账.md`（下划线开头，**不编号、不进索引**） |
| 截图 | `<NN>-<模块代号>-<界面英文名>.png`；英文名 kebab-case、纯 ASCII，后缀 `-page`/`-tab`/`-dialog`，新增态加 `add-` |

## 4. 每册骨架

```markdown
# <NN> · <册名>

> 返回索引：[README](../README.md) ｜ 上一册：[<NN-1>-<名>](./<NN-1>-<名>.md) ｜ 下一册：[<NN+1>-<名>](./<NN+1>-<名>.md)

> <范围说明：本册覆盖什么、与哪些册的关系、截图不完整时以源码为准>

<正文：按册类型的固定小节，见 templates/>
```

- 首册 `上一册：—`，末册 `下一册：—`。
- 相对链接：同目录用 `./<文件>`；跨目录用 `<模块目录>/<文件>` 或 `../<文件>`。

## 5. 索引（README.md）

全局 README 至少包含：模块分节 → **文档索引表**（册 / 文档链接 / 内容）→ **后端接口文档（索引）** → **页签与分区复用矩阵** → **界面截图**（表格 + 命名规则）→ **逐层映射**（遗留→新系统）→ **迁移通用约定** → **推荐落地流程**。

索引表**第一行为「通用」行**，指向跨模块的 `00-前端布局规范.md`；其后才是本模块的 `00-总览与通用约定.md` 起各册。

多模块时按模块分节；每模块一节，索引表行形如 `| <NN> | [<册名>](./<NN>-<模块名>/<NN>-<册名>.md) | <一句话内容> |`。

> 增删册后**必须同步**索引表的行与册号（`audit-docs.sh` 会检查链接可达，但册号列需人工核对）。

## 6. 交叉引用

- 通用内容指向 `00-前端布局规范.md`（跨模块）或本模块 `00-总览与通用约定.md`，**不复制**。
- 共用页签 / 分区指向复用矩阵册 §1。
- 数据模型与接口的具体端点，指向**后端仓库**的接口清单文档（权威），本册只写概要与缺口。

## 7. 进度台账（`_进度台账.md`）

多轮协作的载体：当前状态 / 册规划与进度表 / 待确认问题（阻塞项）/ 修订记录 / 遗留 TODO 汇总。状态取值：`待规划`/`待起草`/`待用户确认`/`修订中`/`已确认`/`待源码复核`/`阻塞`。
