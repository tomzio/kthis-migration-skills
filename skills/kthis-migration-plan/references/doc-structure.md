# 目录结构与文档约定

> 本文件定义迁移文档的**形态**（放哪、叫什么、怎么编号、怎么互相引用）——都是**通用规则**，与具体模块无关。迁移文档根目录默认 `docs/migration/`（脚本 `--root` / `--docs-dir` 可覆盖）。

## 1. 位置

```text
<迁移文档根目录>/
├── README.md                 # 全局索引
├── 00-前端布局规范.md          # 跨模块布局基准（只一份，可选）
├── images/                   # 全模块共享截图目录
└── <NN>-<模块名>/             # 每个功能模块一个目录
```

- `<NN>` 两位序号（`01`、`02`…），与迁移清单 / 既有文档保持一致；`00` 保留给跨模块通用册。
- `<模块名>` 用中文功能名，不用代码代号。
- 截图建议放迁移文档根目录下的共享 `images/`（用**文件名前缀**区分模块）；大模块也可在本模块目录内自建 `images/`。两种都被 `audit-docs.sh` 识别。

## 2. 册（volume）划分原则（最重要）

1. **按界面 / 功能聚合**，不按代码分层；Page 级以第 2 条为准（每个 Page 页面单独一册）。
2. **一个 Editor 可能包含多个 Page；每个 Page 对应一个 WebHIS 页面，并单独成册**：先枚举 Editor 下的 Page / CTabItem / 子页面，写清「Editor → Page → WebHIS 页面」从属关系；每个 Page 页面单独一册，不要按 Editor 一对一拆册，也不要漏 Page。
3. **弹窗的每个页签单独一册**（避免第一版巨型文档）。
4. **弹窗外壳单独一册**（只写外壳，页签正文各归各册）。
5. **共用内容单独一册**：被多个界面共用的页签、共享分区 → 复用矩阵册；**只维护一处**。
6. 收尾固定三册：**数据流程与接口**、**迁移实施计划**、**共享分区与复用矩阵**（顺序可微调但要连续）。
7. 编号**从 00 连续**，不跳号；`00` 必为「总览与通用约定」。
8. **表单归属与册结构：先判定页面类型，禁止一刀切**：
   - **维护 / 设置类列表页**：主页面册只写列表、查询条件与列表操作，不写添加 / 编辑 / 明细维护表单及其保存动作；**查询条件表单属于主页面册，不拆出**。维护表单（字段表、校验、保存按钮、明细列表）单独成册：多页签大表单拆 `shell` + `tab`，单表单弹窗用 `dialog`。
     查询条件中的编码类 / 描述类 / 拼音码类语义字段（按语义识别，不按字面名），用一个 `Input.Search` 聚合搜索同时匹配这些字段，不要拆成多个输入框；其它语义条件按普通查询控件写。
   - **默认页面形态**（表单页、文档编辑器、向导页、详情页、查询 / 报表页）：表单可留在页面主体，按该页面册描述，不强制拆弹窗 / 表单册；表单页 / 编辑器的册名可为「<表单页>」，不强行造空主页面册。
   - **无法判定页面类型时**（如遗留 `*FormPage`）：不要自行假设，先让用户在 **A. 维护 / 设置类列表页（表单进弹窗）** 与 **B. 默认页面形态（表单留页面主体）** 中选择，再排册。
   - 遗留 `*FormPage` 的判别：**上半屏录入 + 下半屏列表 = 维护 / 设置类列表页**，表单进弹窗；独立表单页 / 文档编辑器 / 向导页保持页面主体。

> 上面 8 条是**完整档**的形态。**册集要按功能复杂度裁剪**——简单功能不需要全套，缺册不是缺陷。先定档位（§2.1），再排册。

### 2.1 规模分档（按复杂度裁剪册集）

档位由「界面 / 页签数量、是否存在多界面共用、后端是否已有端点、是否需要阶段计划」决定：

| 档位 | 适用 | 册集 |
| --- | --- | --- |
| **轻量** | 单界面 / 单页签的简单功能，无共用，后端端点已具备 | `00 总览与通用约定`（可精简）+ `01 <页面>`；维护 / 设置类列表页另加 `02 <表单弹窗 / 侧滑>`；默认页面形态的 `01` 即该页面，不另建主页面册 / 弹窗册（见 §2 第 8 条） |
| **标准** | 一个主界面 + 一个编辑弹窗（含若干页签），无跨界面共用 | `00 总览` + `01 <页面>` + `02 弹窗外壳` + `03..k 各页签` + `数据流程与接口` |
| **完整** | 多弹窗 / 多界面共用页签或分区 / 需要阶段计划与门禁 | 标准档 + `辅助弹窗与码表` + `迁移实施计划` + `共享分区与复用矩阵` |

- **不要为「齐整」凑册**：`共享分区与复用矩阵` 只在**确实存在多界面共用内容**时才建；没有就不建，也不留空壳。
- 后端端点已存在且无缺口时，`数据流程与接口` 只需一句话指向后端接口清单（权威）。
- 档位可随对话升级：先按轻量开写，发现共用 / 缺端点后用 `new-volume.sh` 插入册。
- 档位只影响**册数**，不影响**单册正文顺序**（见 §2.3）：轻量档就是把「弹窗外壳 + 各页签」合并进同一册。

### 2.2 公共内容向上提取（三层归属）

多册（甚至多模块）出现同一段内容时，**向上提取到最近的公共层，各册只留一句引用**：

| 重复范围 | 提到哪里 |
| --- | --- |
| 跨模块通用（布局骨架 / 栅格 / 组件对照 / 通用实现清单） | 迁移文档根 `00-前端布局规范.md`（全仓库只一份） |
| 同一模块内多册共用（共用页签 / 共享分区 / 模块级约定 / 系统参数总表） | 模块 `00-总览与通用约定.md` 的通用区；共用页签与共享分区归 `共享分区与复用矩阵` 册 |
| 多个模块文档都出现的同一段（迁移通用约定 / 表结构规约 / SQL 平移写法等） | 迁移文档根 `README.md` 的「迁移通用约定」区（多模块共用一个根） |

- **系统参数总表**：固定放模块 `00-总览与通用约定.md`，列为「参数编码 / 名称 / 默认值 / 用途 / 取值点」；未使用任何参数时也必须保留本节并写「（无）」，不得删节或用 TODO 代替。

操作步骤：`grep` 一个辨识度短语定位所有出现处 → 选最贴近的一处为「家」→ 其余改成「一句话 + 链接」→ 用 `audit-docs.sh --dup-strict` 复检。裁决口径见 [writing-rules.md](writing-rules.md) §5「一册一个家」。

### 2.3 每册内部统一顺序（界面类分册）

```text
（适用条件/参数，可选）→ 功能布局（含线框与布局要点）→ 控件顺序 → UI 交互 → 关联事件 → 实现要点 → 关联文档
```

- 「适用条件（参数）」只在受系统参数 / 权限控制时出现。
- 「功能布局」节末尾含**线框与布局要点**（本界面 ASCII 线框 + 布局要点）；末节「实现要点」只列本册特有实现做法。
- 通用骨架 / 栅格 / 实现做法引用跨模块的 `00-前端布局规范.md`（骨架与栅格见 §3，通用实现清单见 §3.5）。

**册序通用形态（完整档）**（把 `<...>` 换成实际内容，可按需增删页签/弹窗）：

```text
00 总览与通用约定
01 主页面
02 <弹窗甲>编辑弹窗外壳
03..k <弹窗甲>各页签（每页签一册）
     <弹窗乙>编辑弹窗外壳
     <弹窗乙>各页签
     <独立弹窗>
     辅助弹窗与码表
     数据流程与接口
     迁移实施计划
     共享分区与复用矩阵
```

## 3. 文件与命名

| 项 | 规则 |
| --- | --- |
| 册文件 | `<NN>-<册名>.md`，册名用中文界面名 |
| 册名后缀 | `主页面` / `…编辑弹窗外壳` / `…页签` / `…弹窗` |
| 台账 | `_进度台账.md`（下划线开头，**不编号、不进索引**） |
| 截图 | 命名 `<NN>-<模块代号>-<界面英文名>.png`（英文名 kebab-case、纯 ASCII）；识别 / 改名 / 引用更新流程见 [screenshots.md](screenshots.md) |

## 4. 每册骨架

```markdown
# <NN> · <册名>

> 返回索引：[README](../README.md) ｜ 上一册：[<NN-1>-<名>](./<NN-1>-<名>.md) ｜ 下一册：[<NN+1>-<名>](./<NN+1>-<名>.md)

> <范围说明：本册覆盖什么、与哪些册的关系、截图不完整时以源码为准>

<正文：按册类型的固定小节，见 templates/>
```

- 首册 `上一册：—`，末册 `下一册：—`。
- 相对链接：同目录用 `./<文件>`；跨目录用 `<模块目录>/<文件>` 或 `../<文件>`。

## 5. 索引（README.md）

全局 README 至少包含：模块分节 → **文档索引表**（册 / 文档链接 / 内容）→ **后端接口文档（索引）** → **页签与分区复用矩阵** → **界面截图**（表格 + 命名规则）→ **逐层映射**（遗留 → 新系统）→ **迁移通用约定** → **推荐落地流程**。

索引表**第一行为「通用」行**，指向跨模块的 `00-前端布局规范.md`；其后才是本模块的 `00-总览与通用约定.md` 起各册。

多模块时按模块分节；每模块一节，索引表行形如 `| <NN> | [<册名>](./<NN>-<模块名>/<NN>-<册名>.md) | <一句话内容> |`。

> 增删册后**必须同步**索引表的行与册号（`audit-docs.sh` 会检查链接可达，但册号列需人工核对）。

## 6. 交叉引用

- 通用内容指向 `00-前端布局规范.md`（跨模块）或本模块 `00-总览与通用约定.md`，**不复制**。
- 共用页签 / 分区指向复用矩阵册 §1。
- 数据模型与接口的具体端点，指向**后端仓库**的接口清单文档（权威），本册只写概要与缺口。

## 7. 进度台账（`_进度台账.md`）

多轮协作的载体，**结构与状态取值以模板 [templates/\_进度台账.md.tpl](../templates/_进度台账.md.tpl) 为准**（当前状态 / 册规划与进度 / 待确认问题 / 修订记录 / 遗留 TODO）。每轮结束必须更新进度表状态、修订记录一行与待确认项。
